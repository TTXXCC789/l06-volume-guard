# L06 音量守护交接

L06 Volume Guard restores the selected Bluetooth headset's media volume to about 25% after reconnection. Its correction window is bounded so later manual volume changes remain effective.

## 当前目标与基线

Android 当前版本为 **1.6 / versionCode 7**，源码在 `android/`；构建方式见 [android/BUILD.md](../android/BUILD.md)，使用说明以[根目录 README](../README.md)为准。仓库另保留 `macos/` 的旧 20% 工具，它与手机应用独立。

用户的核心需求是：L06 保持开机，手机断开再连接时，媒体音量自动降至约 25%。已测设备最大音量为 150，目标索引为 38。连接后的 15 秒内进行有限校正，覆盖系统与耳机随后恢复的旧音量；之后用户可以自由调音。扬声器或其他耳机不应被调整。

## 实现关系

| Android 文件 | 职责 |
| --- | --- |
| `MainActivity.java` | 权限、守护状态、用户发起的手机端准备及打开官方 Shizuku |
| `VolumeGuardService.java`、`GuardWindow.java` | 媒体路由监测、15 秒校正窗口和后台生命周期 |
| `ConnectionReceiver.java`、`StartupReceiver.java` | 连接、开机和覆盖安装时恢复已启用的守护 |
| `VolumeTarget.java` | 实际 L06 媒体路由检查与前台调音 |
| `ShizukuBridge.java`、`ShellVolumeService.java` | 授权后的受限 IPC、真实 shell 音频初始化与固定目标调音 |
| `OfflineStartupService.java` | 用户发起的限时启动准备，以及取消、超时、成功和中断后的清理 |

这台 vivo / Android 16 会拦截第三方 APP 的后台音量设置，单纯增加前台服务或辅助功能不能解决。有效后端是官方 Shizuku 启动的专用 UserService，实测以 **UID 2000** 执行调音。APP 和服务各自验证 L06 的设备类型、配置地址和媒体路由；服务校验调用 UID，并且不接受任意 shell 命令。

1.5 增加启动恢复与后端重连。1.6 增加手机端启动准备：完成一次性的 `WRITE_SECURE_SETTINGS` 设置授权后，用户打开手机自己的个人热点，在 L06 APP 点击准备，再进入官方 Shizuku 点击“启动”。已保存的配对通常可复用，首次或失效时仍需官方配对流程。准备会请求约 2 分钟的准备窗口；系统冻结可能延迟清理。它不替用户确认 Shizuku 授权，也不承诺自动开机启动。

准备期间临时改变无线调试设置并保存恢复记录。成功、取消或超时后恢复原值并释放资源；中断后保留恢复记录，下一次进入恢复逻辑时核实原值再清除。不能把“端口曾可连接”当作“Shizuku 正在运行”，也不能把“监测服务存活”当作“后台降音量已就绪”。这项准备依赖系统行为，其他机型或系统更新后的表现必须重新验证。

## 已验证结果与证据边界

| 项目 | 结果与证据层级 |
| --- | --- |
| 1.5 锁屏重连 | 独立实机验收：19 个采样均处于锁屏，媒体音量恢复至 38/150；晚到的旧音量恢复也被再次纠正 |
| 校正结束后手调 | 独立实机验收：窗口结束后手动设置 30/150，保持约 6.19 秒未被覆盖 |
| 后端恢复 | 独立实机验收：音量子服务退出后重新连接；Shizuku 主服务重新启动后 APP 自动接回 |
| 1.6 准备超时 | 独立实机验收：约 120,034 ms 结束，设置回到 0、恢复记录不再 pending、唤醒锁释放；切回桌面期间准备仍运行 |
| 1.6 中断恢复 | 独立实机验收：中断记录被清除；该轮系统已先将设置重置，再由 APP 核实清理，不能据此声称 APP 单独证明了所有中断恢复分支 |
| 1.6 官方启动整合 | 独立实机验收：官方 Shizuku 启动成功，控制服务为 UID 2000，守护实际恢复 38/150 |
| 拔线、完整重启后仅手机启动 | **用户反馈**：使用移动数据和手机自身热点完成启动，随后 L06 约 25%。用户最终澄清未接入外部 Wi-Fi，以此澄清为准 |
| 热点关闭后重连 | **用户反馈**：关闭自身热点后重连 L06，仍降至约 25% |

独立采集的启动整合属于运行中的启动恢复测试，没有替代用户那次完整冷启动验收。该轮界面轨迹曾出现短暂的外部 Wi-Fi 关联，未确认取得 IP 或联网成功；不要用它证明“独立测试全程未关联外部 Wi-Fi”，也不要用它否定用户后来对另一次拔线重启测试的澄清。

系统仍可能短暂恢复较高音量后再被校正，因此不能保证整个重连过程始终不高于 25%。目前没有实际声压、长期电池消耗或所有 Android 机型的验收结论。用户主动强制停止、撤销权限或停用守护时，恢复行为仍受系统与用户选择约束。

## 继续开发

优先保持核心重连效果和已有清理行为。设备地址、签名与密码由本地私有配置提供，不得写进公开仓库；详见 [AGENTS.md](../AGENTS.md) 与构建文档。变更后台调音、恢复或准备逻辑后，按实际改动验证相应路径，并继续区分独立读数与用户反馈。

后续报告应直接说明“哪一版本、哪种启动方式、是否有实际设备验证”。不要把这个项目描述成通用 root 替代方案、自动开机激活器或任意 shell 执行工具。
